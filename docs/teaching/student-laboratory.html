OSINT Recon ToolkitProject 6.1 · Student laboratory

Passive OSINT
evidence review

A supervised offline exercise in footprinting, source interpretation and responsible reporting.

Synthetic training data — not live intelligence. No domain ownership, API keys or provider access is required. Do not contact the fictional identifiers.

1 · Learning objectives

  • Trace a report to its source, mode, target and timestamps.
  • Separate a source statement from an analyst interpretation and an unverified claim.
  • Produce consistent HTML, JSON and CSV evidence with proportionate recommendations.

2 · Required software and setup

Use Python 3.10+, Git and a local browser on macOS, Windows or Linux. Installation may need Internet access; the installed Demo workflow runs offline. Use a new checkout directory.

git clone https://github.com/masud1445/osint-recon-toolkit.git
cd osint-recon-toolkit
git switch feature/academic-release-readiness

macOS / Linux terminal

python3 -m venv .venv
source .venv/bin/activate

Windows PowerShell

py -3 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e '.[test]'
osint-dashboard

If activation is restricted, use .venv\Scripts\python.exe for installation and .venv\Scripts\osint-dashboard.exe to start. Keep one server per data directory.

3 · Run the offline workflow

  1. Open http://127.0.0.1:8765; keep the server Terminal open.
  2. Select New Reconnaissance Assessment → Demo. Submit without a target, sources, authorization or license fields.
  3. Review Collection Status, Evidence Review, findings and source JSON. Export HTML, JSON and CSV; retain all synthetic labels.

CLI alternative: osint-recon --demo --output reports/student-lab-001

Use a fresh output directory each time. Open its assessment.html locally. Stop the dashboard with Control-C. Select Live only in a separate, genuinely authorized exercise.

5 · Practical student activities

  1. Provenance: locate mode: offline demonstration, is_synthetic: true and each source’s status: synthetic. Explain why no live approval record is claimed.
  2. Interpretation: write a source statement, cautious interpretation and separately authorized verification question for each source. Do not query fixture assets.
  3. Reconciliation: compare target, mode, source states and findings across exports. CSV observations/findings contain JSON. Review HTML A4 print preview.
  4. Coverage: explain why unavailable/error data cannot justify safety or a Demo fallback. Optional: run python -m pytest to inspect mocked failures.

6 · Submission and expected outcomes

Submit three labelled synthetic exports and a worksheet of source fields, dates, interpretation limits and next steps. Explain provenance, vendor disagreement, scope and coverage gaps. No live access or client approval is implied.
